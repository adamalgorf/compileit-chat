# ADR-0008: User accounts, saved chat history, audit log and secrets in a database

- Status: accepted
- Date: 2026-11-18

## Context

New requirements, beyond the original case:

- users log in with a username and password;
- chat history is saved per user, so it survives a reload and can be reopened from any device;
- all logins and all API calls are recorded;
- no credentials or keys live in the code; the OpenAI key is stored in the database.

There is no database yet, so the structure has to be ready to point at one later.

## Decision

### Storage: SQLAlchemy 2.0 (async) + Alembic, SQLite by default

- `DATABASE_URL` selects the database. Unset, it is a SQLite file under `data/runtime`, which
  needs no server and works in the Docker volume. The schema uses only portable types, so
  PostgreSQL is a URL plus a driver, not a code change.
- The schema is defined once in `infrastructure/persistence/models.py` and evolved with
  **Alembic migrations**. The first migration was autogenerated from the models and then
  reviewed. The API and every CLI command migrate on start (`Container.start()`), and
  `compileit-chat db-upgrade` does it explicitly.
- The agent's memory (LangGraph checkpointer, ADR-0006) stays separate from the *saved
  history* users browse. One is model context; the other is product data with ownership,
  titles and audit needs. Deleting a conversation clears both.

| Table | Holds | Notes |
|---|---|---|
| `users` | username, Argon2id hash | No plain passwords anywhere |
| `auth_sessions` | SHA-256 of the session token, user, expiry | A leaked database cannot be used to log in |
| `login_events` | every attempt: username, success, client IP, time | Security audit |
| `conversations`, `messages` | per-user history, answer sources and status | Cascades on delete |
| `api_calls` | every `/api/chat`: user, question, answer, sources, tool calls, status, latency | No foreign key: the audit record outlives a deleted conversation |
| `secrets` | the OpenAI key, Fernet-encrypted | The master key is *not* in the database |

### Authentication: server-side sessions in an HttpOnly cookie

- Login returns an opaque random token (256 bits) in an `HttpOnly`, `SameSite=Lax` cookie
  scoped to `/api`, with `Secure` configurable for HTTPS. Only its hash is stored.
  - Chosen over JWT: there is no signing key to manage (which would again be a secret in
    the environment), logout really revokes, and the browser's JavaScript never sees the
    token, so XSS cannot steal it.
- Passwords are hashed with **Argon2id** (argon2-cffi defaults). Unknown usernames are
  verified against a dummy hash, so response timing does not reveal which accounts exist, and
  every failure returns the same message.
- **Accounts are created by an administrator** (`compileit-chat create-user`). There is no
  open registration for an internal tool. Passwords are prompted hidden or read from
  stdin, never passed as arguments that end up in shell history.
- Login attempts are rate-limited per client IP, and chat requests per user.
- **Isolation:** another user's conversation answers `404`, exactly like a missing one, so
  ids cannot be probed. This is enforced in the use cases, not the routes, and tested at
  both levels.

### Secrets: encrypted in the database, master key in the environment

"Store the API key in the database" is only meaningful if reading the database is not
enough to obtain the key. So it is stored encrypted with Fernet, and the decryption key
(`SECRETS_MASTER_KEY`) comes from the environment. This is the usual envelope pattern.
Plain-text storage would only move the secret from `.env` into a file that backups and
dumps copy around. `OPENAI_API_KEY` remains as an explicit fallback for development and CI.

### Clean Architecture unchanged

New ports (`UserRepositoryPort`, `PasswordHasherPort`, `AuthSessionStorePort`,
`LoginEventLogPort`, `ConversationRepositoryPort`, `ApiCallLogPort`, `SecretStorePort`,
`ClockPort`) and use cases (`Login`, `Logout`, `Authenticate`, `CreateUser`,
`ChatWithHistory`, `List/Get/DeleteConversation`, `StoreSecret`). `import-linter` now also
forbids `sqlalchemy`, `alembic`, `argon2` and `cryptography` in `domain` and `application`.
`ChatWithHistory` wraps the unchanged `AskQuestion`, so the agent knows nothing about users.

## Consequences

- A stream the user stops is saved as `stopped` with the text that was shown: the save is
  shielded from the request's cancellation.
- `api_calls` contains questions and answers, which is personal data. A production setup
  needs a retention policy (e.g. 90 days) and access control on the database.
- Not built yet, and the next steps: password change and reset, deactivating or deleting
  users, a cleanup job for expired sessions, master-key rotation (re-encrypt), and SSO.
- SQLite allows one writer at a time, which is fine for one API process. Several replicas
  need PostgreSQL, which is a configuration change.
